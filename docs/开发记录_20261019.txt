一、项目概要
================================================================================
项目        中国石油大学（华东）AstrBot 查询插件「石大查询」
起点        GitHub 上的 InformationQuerySystem（2016 年项目）分析
最终版本    1.3.2
开发时间    2026-10-18 21:33 → 2026-10-19 12:23（跨夜，约 14.8 小时）
GitHub      https://github.com/kujochisaki3378/astrbot_plugin_upc
作者        kujochisaki
许可        MIT
插件体积    发布包 32 KB（限制 16 MB）

功能一览
  - 空教室查询 / 附近教室（免登录）
  - 图书馆座位：实时空座、房间统计、座位示意图、找安静座位、黑名单、我的预约
  - 座位时间段筛选（整段可约）
  - 智慧校园课表：本周 / 今天 / 明天 / 周X / 第N周
  - 每日 23:00 自动推送明天课表
  - Telegram 菜单：9 条（含 4 个 ASCII 快捷入口）
  - CAS 自动登录 + token 自动续期

二、完整对话时间线
================================================================================
【阶段 1｜10-18 21:30 起】旧项目调研
  用户：发来 github.com/upcyiban/InformationQuerySystem，要求看看这个项目
  处理：阅读仓库（Spring Boot 1.3.3 + Axis SOAP），确认数据源
        pws.upc.edu.cn 域名已注销（NXDOMAIN），项目无法复活
  结论：不可复用，仅作参考

【阶段 2】能否接入 AstrBot + 空教室可行性
  用户：对此 0 知识，问能否接入 AstrBot
  处理：探测校园系统，发现空教室接口公开无需登录：
        POST app.upc.edu.cn/freeclass/wap/default/search-all
  产出：upc_freeclass.py（命令行工具）

【阶段 3】图书馆座位系统逆向
  用户：想接入图书馆座位
  处理：逆向 libspace.upc.edu.cn
        - 签名：HMAC-SHA256("seat::uuid::ms::METHOD", "leos3cr3t")
        - token 只能放 ?token=，不能放 Authorization 头
        - 座位图坐标 key = row*1000 + col
        - 打通 CAS 登录换 token 全流程
  产出：upc_library.py、cas_login.py

【阶段 4】AstrBot 插件 v1.0.0
  处理：把空教室/附近/图书馆封装成插件，纯 Python 画座位图 PNG
  产出：astrbot_plugin_upc v1.0.0，远程重载脚本 astrbot_reload.py

【阶段 5】功能增强
  - 地图标座位号（内置 3x5 点阵字体）
  - 座位黑名单（地图深灰 + 不推荐）
  - 时间段筛选（/图书馆 地图 2 08:00-10:00）
  - WebUI 密码重置（astrbot_reset_password.py）

【阶段 6｜10-19 上午】地图差异 + 分页 bug
  用户：反馈"我这边查到的空位多很多"
  处理：发现 searchSeats 每页 25 条、代码只取第一页
        修复后：房间6 08:00-10:00 从 25 → 153（与手机端一致）
  版本：1.1.1

【阶段 7】云打印调研（搁置）
  用户：发来 print-library.upc.edu.cn
  处理：摸清 Cprint 云打印系统登录（RSA 加密密码）、上传接口
        结论：登录是 CAS + ASP.NET Identity 双层，密码走不通
        方案：扫码后复用 Cookie（已写好 print_upload.py，搁置）

【阶段 8】资料汇总
  用户：要求把找到的信息写成 txt
  产出：石大查询项目_资料汇总.txt（含全部接口、踩坑、待办）

【阶段 10】智慧校园课表

三、DSH 使用情况
================================================================================
模型        deepseek-flash（deepseek-account）
会话形态    Telegram → AstrBot dsh 桥接插件 → DSH

主要用到的能力：
  1) 本机命令执行：bash / PowerShell（Windows 沙箱）
  2) 文件读写：源码补丁、文档、构建脚本
  3) HTTP 接口探测：urllib 直接调学校接口 + 抓取前端 JS 分析
  4) AstrBot 管理 API：用 dashboard.jwt_secret 签 JWT
     - POST /api/plugin/reload（远程重载插件）
     - GET/PUT /api/v1/system-config（重置 WebUI 密码）
     - PUT /api/v1/bots/by-id（改 Telegram 平台配置并热重载）
  5) Telegram Bot API：setMyCommands / getMyCommands
  6) 后台任务：token 有效期探针（6 小时上限，实测 30 分钟后失效）
  7) 插件内定时任务：asyncio 后台循环，每天 23:00 推送

典型工具调用规模（估算）：
  - 命令执行：约 150+ 次
  - 文件读写/补丁：约 80+ 次
  - 网络探测：约 60+ 次
  - 插件重载：13 次（10-18 晚 7 次 + 10-19 上午 6 次）

后台/常驻物：
  - AstrBot 插件 astrbot_plugin_upc（常驻）
  - 每日推送任务（插件内 asyncio）
  - 临时探针 token_ttl_live.py（已完成，已退出）
